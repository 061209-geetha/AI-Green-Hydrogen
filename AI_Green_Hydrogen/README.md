# AI-Enhanced Integration of Green Hydrogen in Urban Infrastructure for Carbon-Neutral Cities

Research-oriented executable Python implementation accompanying the supplied methodology (sections 4.1–4.6, Table 5 and available part of 5.1). Contains an integrated forecasting → station placement → pipeline corridor → emissions evaluation workflow, reproducible DEMO data, real-data adapters, unit tests, benchmarks, and publication-quality figures.

**Quick start (no downloads):**

```bash
pip install -r requirements.txt
python run_pipeline.py --mode demo --epochs 3 --n-households 20 --days 110 --output outputs/demo_smoke
python -m unittest discover -s tests -v
```

For detailed instructions, see `HOWTORUN.txt`.

## Key architectural choices

- PyTorch stacked LSTM (128/64 hidden) with dropout 0.2 and dense 32→1; a TensorFlow/Keras backend additionally implements the paper's `recurrent_dropout=0.1`. Input is 24 preceding complete days, plus standardised UCI-derived static features and ACORN one-hot indicators. Early stopping and learning-rate scheduling operate on validation MSE; held-out last 15% is never used to train.
- UCI energy-efficiency regressors and an explicitly **assumed** ACORN-to-building archetype crosswalk. Household heating is **synthesised** from degree-days and calibrated against official annual gas use. No claim that either feature was recorded for LCL households.
- Capacity/radius constrained mixed-integer siting (SciPy HiGHS), route-network path costs, and a shared-corridor Steiner-tree approximation. Unlike the paper's simplified algorithm, station capacity is enforced in the candidate assignment. MILP site selection minimises approximate connections; a post-solve Steiner topology is evaluated separately; no global integrated optimality is claimed.
- Distinct conventional planning baseline: Euclidean fixed-4 p-median, radial non-shared network routing, and radius applied only in coverage evaluation.
- Component-wise electricity/gas carbon accounting, mass-based production emissions, four substitution levels, multiple intensity settings, and coverage-adjusted simulation.

## Reproducibility and boundaries

This repository does **not** attempt to force agreement with numbers printed in the manuscript. Critical geocoded study details were not provided: exact London 5×5-km area polygon, anonymised ACORN-to-dwelling crosswalk, 38 validated candidate sites, and supply-hub coordinate. The actual LCL trial measures electricity, **not residential gas**. Synthetic demonstration data and provisional OSM candidate locations must be distinguished from primary observed data. Run manifests mark every assumption.

The default pipeline provides four forecasting comparators; `--full-benchmarks` additionally runs persistence, seasonal-naive, penalized regressions, tree ensembles, KNN, SVR, MLP, XGBoost (when installed), GRU, TCN, CNN-LSTM and Transformer (up to sixteen comparisons). These are reference implementations rather than verified copies of all fifteen manuscript benchmark configurations; SARIMA per household is not implemented. It implements a p-median distance-only baseline and a capacitated graph-based siting method, not every siting comparator reported in Section 5. The 50-m buffers and validated brownfield eligibility require source GIS parcel layers; they are not fabricated by this code. Weather has to span the entire meter period; otherwise the pipeline stops rather than imputing unknown dates silently.

### Forecast-driven planning mode

The default GIS demand is calculated from the learned LSTM forecast and scaled to 25,400 dwellings, directly coupling the model to station siting. A documented reference-inventory alternate (`spatial.demand_source: reference_inventory`) is provided for the manuscript baseline and capacity-planning comparisons. Each run records which source was actually used. Forecast saliency plots are generated by default; `--shap` requests optional SHAP GradientExplainer when SHAP is installed.

## Outputs

All generated numerical results are recomputed from input data. CSVs, model checkpoints, metadata, deterministic splits, spatial map figures (600 DPI), and carbon-scenario plots are written to the designated output directory. This is a software research simulator, not a safety-certified hydrogen infrastructure engineering tool.

## Repeated runs

`python run_experiments.py --seeds 0 1 2 3 4 --mode demo --epochs 100 --output outputs/five_seeds` independently executes five pipelines and records mean and sample SD. `--shap` adds a GradientExplainer analysis for Torch; the default attribution is gradient saliency and is not mislabeled as SHAP.
